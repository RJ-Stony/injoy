## 사용자가 정한 것

- 구조: 시리즈 하나가 책 한 권, 글은 그 책의 장. 시리즈 밖의 글은 한 장짜리 낱권. 홈은 서가와 그래프.
- 글꼴은 기존 Wanted Sans 그대로. 명조는 쓰지 않는다.
- 색은 광이 없는 밝은 파스텔. 그라데이션, 무늬는 쓰지 않는다(둘 다 써 봤다가 뺐다).
- 책 표지는 시중의 책처럼 그림이 있어야 한다. 그림체는 **과슈 물감(붓 자국이 보이는 그림)**으로 정했다.
- 책은 눌러서 먼저 고르고, 고른 책을 다시 눌러야 펼쳐진다. 책을 바꾸는 시간은 마우스든 화살표든 같아야 한다.
- 전환은 끊기지 않고 이어져야 한다. 구분선은 화면이 그려지기 전에 먼저 움직이고, 그 뒤에 글이 올라온다.
- 문장 표현: '뺌', '셈' 같은 깎은 종결을 쓰지 않는다. 묻는 말은 친근하게 쓴다(메모리에도 있다).

## 전환이 움직이는 방식

1. 서가에서 책을 펼치면 표지 크기의 판이 종이색으로 바뀌며 화면을 덮고, 그 뒤에 이동한다(`Shelf.astro`의 `open`). 돌아오면 거꾸로 접힌다(`close`, `sessionStorage`의 `injoy:opened`).
2. 떠나는 화면이 `sessionStorage`의 `injoy:turn`에 구분선의 자리를 적는다(`page-turn.ts`). 도착한 화면의 `Rule.astro`가 그 자리에서 제자리로 줄을 움직인다. 기록에 자리가 없으면 왼쪽에서 그어진다.
3. `BaseLayout.astro`의 인라인 스크립트가 `html[data-arrive]`를 붙이고, `global.css`의 `sheet-rise`가 `.rise` 요소를 한 줄씩 올린다.
4. 뒤로/앞으로 가기는 누르는 순간을 가로챌 수 없어서 떠나는 효과가 없다. `pagehide`에서 기록을 남기고 도착 쪽에서 같은 순서로 나타난다.

글에서 떠날 때는 글줄과 함께 옆의 목차(`.toc-aside`)와 조회 수 줄(`.meta-stats`)도 빠진다(`page-turn.ts`의 `leaving`).

이동 시나리오 점검 도구가 세션 임시 폴더에 있었다(`nav-test.mjs`, `shot.mjs`). 임시 폴더는 지워질 수 있으니 필요하면 다시 만든다. 하는 일은 headless Chrome을 CDP로 몰아 18가지 이동 뒤의 주소, 로고의 가로 위치, 남은 덮개, 숨은 내용, 오류 수를 기록하는 것이다. 마지막 실행에서 18가지 모두 통과했고 오류는 0건이었다.

## 표지 그림 (8권 모두 넣음)

- Codex CLI의 이미지 생성(`~/.claude/skills/codex-imagegen`)으로 만든다. 사용자의 ChatGPT 플랜 사용량에서 차감된다. **한 번에 한 장씩 돌린다.** 여러 장을 동시에 돌리면 파일을 서로 가져가 실패로 찍힌다.
- 과슈 물감 그림체, 제목 글자는 그림에 넣지 않는다(그림 위쪽 40%를 비우고 글자를 HTML로 얹는다). 책마다 표지 색에 맞춘 파스텔.
- 책별 주제: RAG 시스템 구축(도서 카드함), 하네스 엔지니어링(지지대를 타는 덩굴), 블로그 다듬기 기록(대패와 대팻밥), 소프트웨어 설계(제도 도구), 포트포워딩(등대와 작은 항구), Injoy 글쓰기 문법(만년필과 잉크), 글 올리기 귀찮아서 만든 구조(창밖으로 나는 종이비행기), Injoy를 시작하며(화분의 새싹).
- 넣는 순서: 원본을 `01.png`~`08.png`(서가 순서)로 모은 폴더를 두고 `npm run build` → `node scripts/make-covers.mjs <폴더>` → 다시 `npm run build`. `Shelf.astro`는 `public/covers/<열쇠>.webp`가 있으면 표지에 쓰고 없으면 단색 표지와 꼬리표를 쓴다.
- 8권 모두 만들어 `public/covers/`에 넣었다(합쳐서 약 340KB). 원본 PNG는 세션 임시 폴더에만 있고 저장소에는 없다. 6권(Injoy 글쓰기 문법)의 표지는 다른 책보다 색이 진하다.

## 같은 날 이어서 한 것

- 책의 색(`books.ts`의 `cloth`)은 표지 그림의 위쪽 3분의 1의 평균색에서 얻는다. 책등, 윗면, 홈 그래프의 점이 같은 색을 쓴다. 그림이 없는 책만 `CLOTH` 목록의 색을 쓴다.
- 머리말 메뉴는 테두리 하나로 묶은 띠다. 지금 화면의 메뉴는 짙게 채운다(`aria-current`). 모바일 메뉴는 햄버거가 있는 왼쪽에서 열린다.
- 옆 칸(나란히 읽기)은 왼쪽 경계를 끌어 너비를 바꾼다. 너비는 `localStorage`의 `injoy:pane-w`에 남고, 두 번 누르면 처음 너비로 돌아간다. 왼쪽에 720px은 남긴다.
- 홈 그래프: 올렸을 때는 지도만 밝히고, 눌렀을 때만 옆 칸이 바뀐다. 옆 칸의 내용은 한 줄씩 올라오고, 확대 단추와 초기화는 이어서 움직인다.
- 글에서 떠날 때는 글 아래의 시리즈 목록, 연결된 글, 이전·다음 글도 함께 빠진다. 구분선이 화면 밖에 있으면 자리를 적지 않아 다음 화면의 줄이 왼쪽에서 그어진다.
- 서가에서 맨 앞이나 맨 뒤의 책을 골랐을 때 한쪽으로 쏠리는 것은 사용자가 괜찮다고 했다. 그대로 둔다.
- 사용자가 승인해 `main`에 병합하고 push했다.

- 일곱 번째(배포함): 통계 화면이 GA4의 최근 28일 수치를 보여 준다(`src/utils/ga.ts`, 속성 ID 564825050, 열쇠는 환경 변수 `GA4_SA_KEY` 또는 `~/.injoy/ga-key.json`). 열쇠가 없으면 그 구역을 숨긴다. 배포는 하루에 한 번 다시 빌드한다(`deploy.yml`의 schedule). 통계 화면도 `Sheet` 틀로 옮겼다. 두꺼운 책의 책등 제목도 흰 꼬리표 대신 책의 색 띠를 쓴다. GitHub Secret `GA4_SA_KEY`는 사용자가 직접 넣어야 한다(에이전트가 넣지 않는다).

- 여덟 번째(배포함): 꼬리말의 방문 수와 글의 조회 수는 빌드할 때 박는다. 예전 계수기(Abacus)의 값은 2026-11-17에 `src/data/view-baseline.json`에 적어 두었고(`scripts/snapshot-views.mjs`, 다시 돌리지 않는다), 2026-11-18부터 GA4가 센 값을 더한다(`src/utils/views.ts`, `ga.ts`의 `getLifetime`). Abacus 호출은 모두 없앴다. 꼬리말은 머리말처럼 화면 폭 전체를 쓴다. 홈의 첫 화면은 책장이 화면 높이를 채우고, 그래프는 내려와서 화면에 들어올 때 나타난다.

- 아홉 번째(배포함): 모바일 점검. 책장은 화면 폭에 맞춰 크게(`--H: min(96vw, 46svh)`), 휴대폰에서는 면의 종이 결을 빼고 바뀐 책만 스타일을 다시 쓴다(버벅임 대책, 실제 기기에서는 미확인). 좁은 화면(1100px 미만)에서는 옆 칸을 열지 않고 그 글로 바로 넘어간다. 홈 그래프는 책 이름표를 지도 아래의 색 점 목록(`.hm-legend`)으로 빼고 확대 단추를 왼쪽 아래에 둔다. 예전 조회 수 저장에서 글 두 편이 요청 실패로 0이 됐던 것을 다시 받아 고쳤다(`snapshot-views.mjs`는 이제 실패를 0으로 적지 않고 다시 묻는다).

- 열 번째(배포함): 표지 그림은 큰 것(1200)과 작은 것(640, `-s.webp`) 두 벌이고 홈에서 미리 받는다(`Shelf.astro`의 preload). 홈 그래프는 두 손가락으로 확대하고(전체 그래프 화면과 같은 방식), 책 이름표는 화면에서 늘 같은 크기로 보인다(`--inv`, 지도 밖으로 나가면 안으로 민다). 검색 결과의 링크는 `?hl=<검색어>`를 싣고, 글 화면이 그 말이 있는 자리로 내려가 잠깐 밝힌다(`src/scripts/search-flash.ts`).

- 열한 번째(배포함): 검색어 자리는 본문 바로 뒤의 인라인 스크립트가 화면이 그려지기 전에 잡는다(`posts/[slug].astro`, `search-flash.ts`는 없앴다). 홈 그래프의 두 손가락 확대는 포인터 이벤트로는 휴대폰에서 받지 못해 터치 이벤트로 바꿨다(두 손가락일 때만 preventDefault). 휴대폰에서는 책 이름표를 숨긴다.

- 열두 번째(배포함): 홈 그래프는 옮기고 확대하는 동안 viewBox를 바꾸지 않고 그려 둔 그림을 transform으로 옮기다가 손을 떼면 한 번만 새로 그린다(`preview`/`commit`, 흐림 필터가 많아 매번 다시 그리면 휴대폰에서 끊긴다). 검색어 자리는 글이 뜨고 0.28초 뒤 부드럽게 내려가며, 닿지 못했으면 다시 맞춘다. 읽기 단추는 꼬리말이 올라온 만큼 따라 올라가 그 위에서 멈춘다(꼬리말의 오른쪽 여백은 되돌렸다).

- 열세 번째(배포함): 홈 그래프는 viewBox를 늘 지도 전체로 두고, 옮기고 확대하는 것은 svg의 transform으로만 한다(`apply`, 멎으면 `settle`이 will-change를 떼어 또렷하게 다시 그리게 한다). 보이는 범위만 그리던 방식은 옮길 때 가장자리가 비거나 매번 다시 그려 끊겼다. 화면 좌표는 `frac`과 `unit`으로 바꾼다(svg의 getBoundingClientRect는 늘어난 크기라 쓰지 않는다).

- 열네 번째(배포함): 홈 그래프는 움직임이 멎으면 그림 자체를 그 배율의 크기로 키워 다시 그린다(`drawnZ`, 늘이기만 하고 두면 확대한 만큼 흐리다. 사파리는 늘인 그림을 다시 그려 주지 않는다). 지도 칸의 크기는 칸이 정하고(`aspect-ratio`) 그림은 그 안에 겹쳐 놓는다. 구글 서치 콘솔과 네이버 확인 태그를 넣었다(네이버는 사용자가 진행하지 않기로 했다). 사이트맵에서 글쓰기와 검색 화면을 뺐다.

- 열다섯 번째(커밋 전): 용어 표기(O4)를 글 39편과 `/voice` 3절에 적용했다. 워커에 나누지 않고 주 세션이 스크립트로 한 번에 고쳤다(가려 둔 곳: 코드 펜스, 인라인 코드, 위키 링크의 대상, 링크 주소, 인용문). 사용자가 정할 것 4가지와 일반어로 보고 둔 자리는 `docs/overhaul-terms.md`의 "적용 결과와 남은 판단"에 있다. 소제목 7개의 글자가 바뀌어 그 소제목으로 바로 가는 바깥 링크는 끊긴다(저장소 안에서 가리키는 곳은 없다). 화면은 브라우저로 열어 보지 않았고 `dist`의 HTML에서 바뀐 말을 확인했다.

- 열여섯 번째(커밋 전): 글 40편을 한국의 산문집처럼 읽히도록 다시 썼다. 기준은 작성자가 문장마다 직접 고친 `harness-3-serena-proxy`이고, 다듬는 순서와 원칙은 `docs/injoy-prose.md`, `/voice`의 "0. 기준"에 있다(`AGENTS.md`의 윤문 항목도 이 스킬을 가리킨다). 워커 열이 시리즈별로 나눠 썼다(앞의 여섯은 Fable, 뒤의 셋은 Sonnet). 주 세션은 40편의 코드 블록과 frontmatter를 원본과 대조했고, 글은 일부만 끝까지 읽었다(`harness-2`, `harness-8`, `polish-round-12`와 몇 편의 도입부). 제목은 `harness-3`만 바꿨다. 워커가 모아 온 제목 후보, 사실이 어긋나 보이는 곳, 작성자에게 물을 것(글마다 두세 가지)은 `docs/post-questions.md`에 옮겨 두었다. 물을 때는 그 대목의 문장을 함께 보여 준다. 감정과 경위는 지어내지 않았으므로, 작성자의 답을 받아 도입과 전환점과 맺음에 넣는 일이 남았다(`harness-3`만 끝났다). 머리말 메뉴가 첫 방문에서 튀던 것은 글꼴 조각 6개를 미리 받게 해서 고쳤다(`BaseLayout.astro`).
