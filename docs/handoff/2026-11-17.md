# 2026-11-17 인수인계: 개편 준비

## 상태

사용자가 블로그 개편(용어 통일, 디자인)을 준비하라고 요청했다. **구현은 아직 하지 않는다.** 용어 표기와 디자인 방향은 사용자가 정하고, 정해지기 전에는 글과 화면을 고치지 않는다.

- 브랜치: 문서와 용어 통일은 `main`에 직접 올리고, UI 개편만 `feat/overhaul`에서 한다(같은 날 사용자가 정했다).
- 만든 것: `CLAUDE.md`(`@AGENTS.md` 한 줄), `AGENTS.md`의 "UI 개편은 기능 브랜치에서"와 "일을 나누는 규칙" 절, [개편 진행표](../overhaul-progress.md), [용어 표기 결정](../overhaul-terms.md), 이 문서.
- 디자인: 엔진(Astro)과 그래프 구조는 유지하고 화면을 전면 개편한다. 토스, 우아한형제들 기술 블로그와는 다른, 포트폴리오가 될 만한 색다른 구조를 원한다. 사용자가 준 참고처는 https://motionsites.ai/ 이다.
- 항목별 상태는 진행표에 있다.

## 일을 나누는 규칙의 출처

bible-rpg 저장소의 `docs/handoff/2026-11-14.md` "일을 나눠 맡기는 방식"을 이 저장소에 맞게 옮겼다. 규칙의 정본은 `AGENTS.md`이고 여기에는 옮기며 바꾼 것만 적는다.

- 공용 파일을 게임의 `main.js`·`props.js`·`field.js`에서 그래프, 스키마, 공용 스타일, 레이아웃, `/voice` 노트로 바꿨다.
- 워커의 단위를 스테이지 파일 하나에서 글 묶음 하나나 화면 하나로 바꿨다.
- 워커가 돌리는 검증을 `npm run check`에서 `npm run lint:wiki`로 바꿨다. 이 저장소에는 `check`가 없고 `npm run build`는 `dist/`를 함께 써서 워커 둘이 동시에 돌릴 수 없다.
- 글을 고치는 워커가 지킬 조건(frontmatter, slug, 위키링크 대상, 코드, 인용문)을 더했다.

## 용어 후보

글 40편을 세 묶음(harness 10편, polish-round 15편, rag와 나머지 15편)으로 나눠 Sonnet 서브에이전트가 후보를 모았고, 주 세션이 전체 글에서 출현 수를 다시 셌다. 사용자가 표기를 정했고 결과는 [용어 표기 결정](../overhaul-terms.md)에 있다. 글에는 아직 적용하지 않았다.

## 재개 순서

1. 정해진 표기를 `/voice` 3절에 적고, 글 묶음별로 워커에 배정한다(O4). 동시에 둘까지. `main`에 올린다.
2. 참고 사례를 조사해 `DESIGN.md` 초안과 시안을 만들고 사용자가 고른다(O5). 그 뒤에 `feat/overhaul`에서 화면별로 구현한다(O6).
3. `npm run build`, `bash scripts/verify.sh`, 브라우저 확인(O7). 사용자가 승인하면 `main`에 병합한다.

## 미확인

- 새 규칙으로 실제 배정을 돌려 보지 않았다. 워커 둘이 동시에 글을 고칠 때 `lint:wiki`가 충분한 검증인지는 첫 배정에서 확인한다.
- 이번에 문서만 바꿨으므로 build와 `scripts/verify.sh`는 돌리지 않았다.
