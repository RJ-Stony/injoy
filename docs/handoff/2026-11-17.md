## 지금 상태

- 브랜치: `feat/overhaul`을 `main`에 병합해 배포했다. 작업 폴더에 커밋하지 않은 것은 없다.
- 확인: `npm run build`와 `bash scripts/verify.sh`가 ALL PASS, `npm run lint:wiki` 통과.
- 보는 방법: `npm run build` 뒤 `npx astro preview --port 4321`로 띄우고 `http://localhost:4321/injoy/`를 연다. **개발 서버(`npm run dev`)로 보여 주지 않는다.** 스타일이 늦게 붙어 전환이 끊겨 보인다.
- 사용자는 화면을 직접 보면서 고칠 점을 말한다. 고친 뒤에는 캡처로 확인하고, 확인하지 못한 것은 그렇다고 적어 보고한다.

## 사용자가 정한 것

- 구조: 시리즈 하나가 책 한 권, 글은 그 책의 장. 시리즈 밖의 글은 한 장짜리 낱권. 홈은 서가와 그래프.
- 글꼴은 기존 Wanted Sans 그대로. 명조는 쓰지 않는다.
- 색은 광이 없는 밝은 파스텔. 그라데이션, 무늬는 쓰지 않는다(둘 다 써 봤다가 뺐다).
- 책 표지는 시중의 책처럼 그림이 있어야 한다. 그림체는 **과슈 물감(붓 자국이 보이는 그림)**으로 정했다.
- 책은 눌러서 먼저 고르고, 고른 책을 다시 눌러야 펼쳐진다. 책을 바꾸는 시간은 마우스든 화살표든 같아야 한다.
- 전환은 끊기지 않고 이어져야 한다. 구분선은 화면이 그려지기 전에 먼저 움직이고, 그 뒤에 글이 올라온다.
- 문장 표현: '뺌', '셈' 같은 깎은 종결을 쓰지 않는다. 묻는 말은 친근하게 쓴다(메모리에도 있다).

- 브라우저의 화면 전환(`@view-transition`)은 껐다. 직접 그리는 전환과 겹치면 화면이 튄다.

## 전환이 움직이는 방식

1. 서가에서 책을 펼치면 표지 크기의 판이 종이색으로 바뀌며 화면을 덮고, 그 뒤에 이동한다(`Shelf.astro`의 `open`). 돌아오면 거꾸로 접힌다(`close`, `sessionStorage`의 `injoy:opened`).
2. 떠나는 화면이 `sessionStorage`의 `injoy:turn`에 구분선의 자리를 적는다(`page-turn.ts`). 도착한 화면의 `Rule.astro`가 그 자리에서 제자리로 줄을 움직인다. 기록에 자리가 없으면 왼쪽에서 그어진다.
3. `BaseLayout.astro`의 인라인 스크립트가 `html[data-arrive]`를 붙이고, `global.css`의 `sheet-rise`가 `.rise` 요소를 한 줄씩 올린다.
4. 뒤로/앞으로 가기는 누르는 순간을 가로챌 수 없어서 떠나는 효과가 없다. `pagehide`에서 기록을 남기고 도착 쪽에서 같은 순서로 나타난다.

글에서 떠날 때는 글줄과 함께 옆의 목차(`.toc-aside`)와 조회 수 줄(`.meta-stats`)도 빠진다(`page-turn.ts`의 `leaving`).

이동 시나리오 점검 도구가 세션 임시 폴더에 있었다(`nav-test.mjs`, `shot.mjs`). 임시 폴더는 지워질 수 있으니 필요하면 다시 만든다. 하는 일은 headless Chrome을 CDP로 몰아 18가지 이동 뒤의 주소, 로고의 가로 위치, 남은 덮개, 숨은 내용, 오류 수를 기록하는 것이다. 마지막 실행에서 18가지 모두 통과했고 오류는 0건이었다.

## 표지 그림 (8권 모두 넣음)

- Codex CLI의 이미지 생성(`~/.claude/skills/codex-imagegen`)으로 만든다. 사용자의 ChatGPT 플랜 사용량에서 차감된다. **한 번에 한 장씩 돌린다.** 여러 장을 동시에 돌리면 파일을 서로 가져가 실패로 찍힌다.
- 과슈 물감 그림체, 제목 글자는 그림에 넣지 않는다(그림 위쪽 40%를 비우고 글자를 HTML로 얹는다). 책마다 표지 색에 맞춘 파스텔.
- 책별 주제: RAG 시스템 구축(도서 카드함), 하네스 엔지니어링(지지대를 타는 덩굴), 블로그 다듬기 기록(대패와 대팻밥), 소프트웨어 설계(제도 도구), 포트포워딩(등대와 작은 항구), Injoy 글쓰기 문법(만년필과 잉크), 글 올리기 귀찮아서 만든 구조(창밖으로 나는 종이비행기), Injoy를 시작하며(화분의 새싹).
- 넣는 순서: 원본을 `01.png`~`08.png`(서가 순서)로 모은 폴더를 두고 `npm run build` → `node scripts/make-covers.mjs <폴더>` → 다시 `npm run build`. `Shelf.astro`는 `public/covers/<열쇠>.webp`가 있으면 표지에 쓰고 없으면 단색 표지와 꼬리표를 쓴다.
- 8권 모두 만들어 `public/covers/`에 넣었다(합쳐서 약 340KB). 원본 PNG는 세션 임시 폴더에만 있고 저장소에는 없다. 6권(Injoy 글쓰기 문법)의 표지는 다른 책보다 색이 진하다.

## 남은 일

1. 표지 그림은 넣었다. 사용자가 보고 말하는 점을 고친다(6권의 진한 색, 제목과 그림이 겹치는 책, 책등에 그림의 색을 이을지).
2. 사용자가 직접 보고 말한 전환의 어색한 구간을 고친다. 움직이는 중간 장면은 캡처로 일부만 확인했다.
3. 용어 통일(O4): `docs/overhaul-terms.md`의 표기를 글 40편에 적용하고 `/voice` 3절에 옮긴다. 아직 시작하지 않았다.
4. 그래프 화면(`/graph`), 용어 사전, 검색, 글쓰기 화면은 색과 머리말만 바뀌었다. 화면 구조는 손대지 않았고 글쓰기 화면은 열어 보지 않았다.
5. 관계 자동 판정(글을 발행할 때 LLM이 엣지 후보를 만드는 것)은 설계만 말하고 만들지 않았다.
6. 사용자가 승인하면 `feat/overhaul`에 커밋하고, 그 뒤에 `main` 병합을 묻는다.

## 캡처로 확인한 것 (세션을 이어받은 뒤)

- 표지 8권 모두, 다크 화면, 390px 화면, 홈의 등장(책이 올라와 꽂힘), 글에서 로고로 홈에 나가는 중간 장면.
- 이동 점검 도구의 선택자 하나가 낡아 있었다(`a.book-line` → `.book-bar .back`). 고친 뒤 18가지가 모두 맞는 화면에 도착했다. 점검 도구는 누를 요소를 찾지 못해도 오류로 세지 않으니, 결과의 `path`를 눈으로 대조한다.
- 보고 알게 된 것: 표지 그림(특히 5, 7, 8권)은 책등의 파스텔보다 진하다. 맨 앞이나 맨 뒤의 책을 고르면 서가가 한쪽으로 쏠려 반대쪽 끝의 책이 화면 밖으로 잘린다(1440px 기준). 둘 다 사용자에게 물을 것.

## 같은 날 이어서 한 것

- 책의 색(`books.ts`의 `cloth`)은 표지 그림의 위쪽 3분의 1의 평균색에서 얻는다. 책등, 윗면, 홈 그래프의 점이 같은 색을 쓴다. 그림이 없는 책만 `CLOTH` 목록의 색을 쓴다.
- 머리말 메뉴는 테두리 하나로 묶은 띠다. 지금 화면의 메뉴는 짙게 채운다(`aria-current`). 모바일 메뉴는 햄버거가 있는 왼쪽에서 열린다.
- 옆 칸(나란히 읽기)은 왼쪽 경계를 끌어 너비를 바꾼다. 너비는 `localStorage`의 `injoy:pane-w`에 남고, 두 번 누르면 처음 너비로 돌아간다. 왼쪽에 720px은 남긴다.
- 홈 그래프: 올렸을 때는 지도만 밝히고, 눌렀을 때만 옆 칸이 바뀐다. 옆 칸의 내용은 한 줄씩 올라오고, 확대 단추와 초기화는 이어서 움직인다.
- 글에서 떠날 때는 글 아래의 시리즈 목록, 연결된 글, 이전·다음 글도 함께 빠진다. 구분선이 화면 밖에 있으면 자리를 적지 않아 다음 화면의 줄이 왼쪽에서 그어진다.
- 서가에서 맨 앞이나 맨 뒤의 책을 골랐을 때 한쪽으로 쏠리는 것은 사용자가 괜찮다고 했다. 그대로 둔다.
- 사용자가 승인해 `main`에 병합하고 push했다.

## 미확인

- 실제 휴대폰에서의 움직임과 두 손가락 확대.
- 댓글(giscus)은 로컬에서 글자색이 빠진다. `https` 창 안에서 `http://localhost`의 CSS를 막기 때문이고 배포에서는 정상일 것으로 본다. 댓글 테마 파일의 글자색과 테두리색은 예전 값 그대로라 배포 뒤에 봐야 한다.
- Chrome과 Edge가 아닌 브라우저에서의 모습.

- 책 밖의 화면(목차, 카테고리, 태그, 검색, 용어 사전, 그래프, About)이 같은 틀을 쓴다: `src/components/Sheet.astro`(맨 위 구분선, 왼쪽 제목, 오른쪽 내용. 그래프는 `stack`으로 제목을 위에 둔다). 글 목록의 줄은 `src/components/PostRows.astro` 하나다.
- 표기: "N개의 장"은 "N개의 글"로 바꿨다. 목차의 "N권 가운데 M권"과 글 화면의 "N개의 장 가운데 M장"은 없앴다. 기간은 "2026.06.27 ~ 2026.07.12"로 적는다.
- 서가는 처음 들어오면 1권부터 보여 준다. 책을 펼쳤다가 돌아오거나 뒤로 가기로 올 때만 보던 책에서 이어진다.
- 낱권의 책등은 제목을 한 줄로 세운다. 글자 크기는 제목 길이(`--len`)에 맞춘다.
- 날짜를 "4개월 전"으로 바꾸는 함수는 `BaseLayout`의 인라인 스크립트(`window.injoyRel`)에 있고, 날짜 바로 뒤의 인라인 스크립트가 화면이 그려지기 전에 부른다.
- 옆 칸: 열릴 때 오른쪽에서 밀려 들어오고, 칸 안의 글도 줄이 먼저 그어진 뒤 글이 올라온다. 칸 안에서 다른 글로 넘어갈 때도 `page-turn.ts`가 같은 효과를 낸다.
- Google Tag Manager: `PUBLIC_GTM_ID`가 있을 때만 태그가 붙는다. 배포에서는 저장소 변수 `GTM_ID`가 들어간다(`deploy.yml`). 컨테이너 ID는 사용자가 만들어서 줘야 한다. GA4 수치를 통계 화면에 보여 주는 일은 GA4 속성 ID와 서비스 계정 키를 받은 뒤에 한다(시작 전).

- 화면에 적는 말은 "서가" 대신 "홈"을 쓴다(사용자 결정). 홈의 그래프 구역은 다른 화면과 같은 결(맨 위 구분선, 큰 제목, 테두리 없는 옆 칸)로 맞췄다. About의 설명은 frontmatter의 줄바꿈을 그대로 보여 준다.
