# Injoy 성장 로드맵 기획 (2026-07-09, 35차 기획 회차)

UX·온톨로지·LLM wiki 관점에서 전 영역(글쓰기·검색·글·그래프·홈)을 훑어 뽑은
30개 후보와 7회차 로드맵. 이 문서는 기획 산출물이고, 구현은 회차별 후속 세션(Opus 4.8)이
`/injoy-iterate` 레일로 집행한다. 각 회차 시작 시 이 문서의 해당 절을 읽고
그 회차만의 상세 계획(writing-plans)을 다시 세운다.

## 원칙 (사용자 확정)

- **정적 사이트 유지.** 런타임 백엔드·API 키 없음. 허용 범위는 빌드타임 자동화와
  발행 시 에이전트 자동화(Karpathy식 "LLM이 사서")까지.
- **데스크톱·모바일 동시 개선.** 한쪽만 좋아지는 작업은 미완성으로 간주.
- **글쓰기(/write)와 글 페이지 동기화.** 글에 보이는 블록·속성은 /write에서 CRUD
  가능해야 하고, 새 메타는 Milkdown 왕복 검증 필수(메모리 '조용한 버그' 함정).
- **과하지도 부족하지도 않게.** 작성자·독자 경험을 해치는 기능은 넣지 않는다.
- voice 감사는 **감사 + 명백한 위반 자동 수정까지**(애매한 것만 보고).
- 의미 기반 관련 글(C10)은 이번 로드맵에 **7회차로 포함**(이전 보류 해제, 사용자 결정).

## 이번 탐색에서 확정한 사실 (2026-07-09 기준)

- 서식 버블: `src/scripts/milkdown-editor.ts:566-653` `makeFormatBubble()`.
  선택 위쪽에 `position:fixed`로 띄움. **터치 분기·iOS 네이티브 선택 메뉴 회피 로직 없음**
  (버튼도 `mousedown`만 리스닝). 모바일에서 커스텀 버블과 iOS 메뉴가 충돌하는 구조.
- PWA 아님: manifest·service worker·`apple-mobile-web-app-*` 메타 전부 없음.
  `apple-touch-icon`(BaseLayout.astro:60)만 존재. `theme-color` 메타도 없음.
- /write 진입: 헤더·모바일 메뉴의 write-link는 `localStorage['injoy-gh-token']`
  있을 때만 노출(BaseLayout.astro:108,154,171-180). standalone(홈 화면 앱)에선
  URL 입력이 불가해 토큰을 넣으러 갈 방법 자체가 없음.
- 검색(`src/pages/search.astro`): Pagefind JS API 직접 호출,
  정렬이 `{ sort: { date: 'desc' } }` **하드코딩**(관련도 무시, :160). 필터 UI 없음.
- `getConnections`(graph.ts:216)는 이미 **양방향**(백링크 포함). 백링크 기능 제안 불필요.
- 이미지 붙여넣기·드래그 업로드 이미 있음(milkdown-editor.ts:731-739). 제안 불필요.
- `[[` 위키링크는 칩 데코레이션만 있고 **자동완성 없음**.
- voice B규칙(용어 첫 등장 괄호 풀이)은 샘플링한 최근 글 후반부(포트포워딩 UPnP·Mirai,
  threading busy-wait)에서도 준수 중. 전수 감사는 여전히 유효하되 위반이 대량은 아닐 전망.

## 후보 전체 목록 (30개)

### A. 글쓰기
- **A1 모바일 서식 도킹 바** (중): coarse pointer(`pointer:coarse`)에서는 떠다니는 버블
  대신 키보드 바로 위 고정 바. `visualViewport`로 키보드 높이 추적. iOS 네이티브 선택
  메뉴와 영역 분리. 데스크톱은 현행 버블 유지.
- **A2 PWA 설치형 웹앱** (소~중): manifest+아이콘+`theme-color`+iOS 메타.
  SW 캐싱은 뺀다(YAGNI, 오프라인 필요 없음). standalone /write 진입은
  manifest shortcuts(안드로이드) + 홈 로고 길게 누르기 이스터에그(iOS, about 🌱 전통 계승).
  주의: iOS standalone의 localStorage는 Safari와 분리라 토큰 재입력 1회 필요.
- **A3 /write 모바일 실기기 점검** (소): 선택 핸들·캡션 편집·스크롤 점프 등
  마찰 목록화 후 일괄 수정. 헤드리스로 못 잡으니 실기기(iOS) 확인 전제.
- **A17 voice 린터** (중): 발행 버튼 옆 "점검". 엠대시·제목 콜론/붙임표·합쇼체·
  `[!code` 언어별 주석 문법 오용 등 기계 판정 가능한 규칙만 클라이언트 정적 검사.
  C11 감사가 규칙을 확정하면 린터가 재발 방지하는 짝 구조.
- **A18 `[[` 위키링크 자동완성** (중, 백로그): `[[` 입력 시 글 제목 드롭다운.
  슬래시 메뉴 패턴 재사용.
- **A19 발행 전 실렌더 미리보기** (중~대, 백로그): mermaid·콜아웃·스텝 마커까지
  실제 글 페이지와 동일 렌더로 보는 모드.

### B. 검색

- **B5 필터 칩** (소~중): 글 페이지에 Pagefind filter 메타(카테고리·시리즈) 심고

### C. 온톨로지 · LLM wiki
- **C7 용어집 자동 생성** (중): 본문의 `**용어**(풀이)` B규칙 패턴을 빌드타임 파싱해
  `/glossary` 페이지 생성(용어·풀이·출처 글 링크). voice 규칙이 이미 구조화된 데이터라
  공짜 온톨로지. 파싱 규칙은 remark 단계에서(오탐 주의: 굵게+괄호가 전부 용어는 아님,
  풀이 길이 5~12자 휴리스틱과 수동 제외 목록 필요).
- **C8 용어 하버카드** (중): 다른 글에서 용어집 용어 등장 시 hover card(데스크톱),
  탭 시트(모바일)로 풀이. 기존 `hover-card.ts`·remark data-속성 패턴 재사용.
- **C9 주제 허브(MOC) 페이지** (중~대, 보류): 태그 승격형 주제 허브. 용어집·태그와
  역할이 겹칠 수 있어 3회차 결과를 보고 백로그에서 승격 여부 판단.
- **C10 의미 기반 관련 글** (대, 7회차): 빌드타임 임베딩(transformers.js bge-m3,
  키 0) 또는 어휘 자카드. 방식 선정은 7회차 시작 시 벤치 후 결정.
- **C11 voice 전수 감사 + 자동 수정** (중): 전 글을 에이전트가 훑어 B규칙 누락·엠대시·
  번역투·제목 규칙 위반을 찾고, 명백한 것은 수정 커밋·애매한 것은 보고. 출처 기준은
  `injoy-voice-guide`. 수정도 voice 말투로.
- **C20 llms.txt + 글별 .md 원문 노출** (소~중): llms.txt 표준으로 사이트 구조·글 목록
  서빙 + 각 글의 원문 마크다운 제공(빌드타임 복사). 다른 LLM이 이 위키를 읽기 좋게.
- **C21 스키마 공개 페이지 + 그래프 범례** (중): 엣지 타입(extends/requires/related/

- **C22 연결 위생 감사** (소~중): 빌드타임에 고아 글(엣지 0)·깨진 위키링크·비대칭 의심

## 회차 공통 주의 (메모리 요약 포인터)

- 각 회차는 `/injoy-iterate` 레일(동기화 → 계획 → 목업 → 구현 → 검증 → 배포 → 메모리)을 탄다.
- UI 갈림길은 AskUserQuestion, 수정 지점 before/after 목업, 다크·라이트·데스크톱·모바일 검증.
- 애니메이션·터치·키보드는 헤드리스로 재현 불가. 코드 추론 + 라이브(실기기) 확인.
- 세션 커밋은 모아서 push 1회(Pages 배포 throttle).
- 새 authorable 메타는 Milkdown 왕복 검증 필수. write.astro는 `grep -a`.
- 글·문구는 `injoy-voice-guide` 먼저. 엠대시 금지(본문·캡션·커밋·코드 주석 전부).
