글이 한 편 두 편 쌓이자, 카테고리별로 글을 모아 볼 수 없다는 것이 눈에 밟혔다. 그래서 이번에는 카테고리별로 글을 모아 보는 기능을 만들었다. [[polish-round|지난 글]]에서 한 차례 다듬은 뒤에도 읽고 쓰는 화면에는 손볼 곳이 남아 있어서, 그것들도 이번에 함께 다듬었다.

## 카테고리로 모아 보기

글이 늘어나면서 블로그, 글쓰기, AI 같은 카테고리가 여럿 생겼다. 그런데 카테고리별로 글을 모아 볼 방법이 없었다. 그래서 헤더에 카테고리 메뉴를 추가했다. 메뉴를 누르면 카테고리 목록이 펼쳐지고, 그중 하나를 고르면 그 카테고리의 글만 모인 페이지로 이동한다. 카드의 카테고리 뱃지를 눌러도 같은 페이지로 이동한다.

새 카테고리를 추가할 때 코드를 수정할 필요는 없다. 글의 frontmatter(글 머리에 적는 정보)에 `category`만 적으면, **메뉴와 페이지가 그 목록을 따라 자동으로 생긴다.** 헤더의 메뉴도, `/categories/블로그/` 같은 페이지도 아래의 함수가 돌려준 목록 하나로 만들어지기 때문이다.

```ts src/utils/post.ts
// 발행 글을 훑어 카테고리별 글 수를 센다(글 많은 순, 같으면 가나다순)
export async function getCategories() {
  const posts = await getPublishedPosts();
  const counts = new Map();
  for (const p of posts) counts.set(p.data.category, (counts.get(p.data.category) ?? 0) + 1);
  return [...counts.entries()]
    .map(([name, count]) => ({ name, count }))
    .sort((a, b) => b.count - a.count || a.name.localeCompare(b.name, 'ko'));
}
```

그래서 어떤 글의 카테고리를 바꾸기만 해도 메뉴와 페이지가 함께 바뀐다. 실제로 이 글도 얼마 전 '개발'에서 '블로그'로 옮겨졌는데, 그 순간 메뉴에서 '개발'이 사라지고 '블로그'가 나타났다.

## 모바일에서는 햄버거 메뉴로

카테고리 메뉴를 만들면서 가장 신경 쓴 것은 모바일이었다. 좁은 화면에서는 메뉴를 햄버거 버튼 안에 모았다. 그리고 글이 한참 늘어나더라도 헤더가 무너지거나 글자가 줄바꿈되지 않도록, 메뉴는 화면의 흐름 밖에 띄웠다.

여기서 작은 문제를 하나 만나게 되었다. 메뉴 안의 링크들을 가지런히 배치하려고 `display: flex`(요소를 가지런히 배치하는 CSS 규칙)를 설정했는데, 이 규칙이 글쓰기 링크의 숨김(`hidden`)을 덮어써 버린 것이다. `display: flex`가 `hidden` 속성보다 우선하기 때문에, 토큰이 없어도 글쓰기 링크가 보이게 되었다. 그래서 `a[hidden]`에 `display: none`을 더 구체적인 규칙으로 다시 지정했다.

```css src/layouts/BaseLayout.astro
.site-header .mobile-menu a {
  display: flex; /* 링크를 가지런히. 그런데 이게 hidden을 덮었다 */
}
/* display:flex가 hidden을 덮지 않도록. 글쓰기 링크는 토큰 있을 때만 보인다 */
.site-header .mobile-menu a[hidden] {
  display: none; /* [!code ++] */
}
```

이 문제는 빌드가 아무 문제 없이 통과했기 때문에, 화면을 직접 보아야만 발견할 수 있었다.

## 글을 작성하는 화면

글을 작성하는 화면에서는 두 군데를 고쳤다. 하나는 기존 글을 고르는 드롭다운이다. 제목이 길면 이 칸이 화면 밖으로 삐져나갔고, 모바일에서는 특히 더 그랬다. 이제는 칸의 폭 안에서만 보이게 하고, 넘치는 부분은 …로 줄인다. 드롭다운을 펼치면 전체 제목이 그대로 보인다.

다른 하나는 연결을 추가하는 자리다. 메모가 세 줄로 답답하게 쌓이던 것을, **타입, 제목, 빼기**를 한 줄에 두고 그 아래에 메모를 한 줄로 내렸다. 또 예전에는 한 번 적은 메모를 고칠 방법이 없었는데, 이제는 그 자리에서 바로 고쳐 쓸 수 있다.

## 읽는 화면

홈 목록에서도 글마다 읽는 시간 옆에 조회수가 보이도록 했다. 다만 목록에서는 조회수를 올리지 않고 조회만 한다. 둘러보는 것만으로 숫자가 부풀면 곤란하기 때문이다.

글 안에서는 조회수가 늦게 표시되어서 줄이 한 번씩 출렁였다. 그래서 자리를 미리 잡아 두고 숫자만 채우도록 바꾸었다. 자리를 미리 잡는다는 것은, 응답이 오기 전에 숫자의 폭만큼 빈 칸을 먼저 그려 둔다는 뜻이다.

```html
<!-- 응답 전: 숫자 폭만큼 잔잔히 반짝이는 자리표시 -->
<span class="value"><span class="vc-skeleton"></span></span>
```

칸이 처음부터 있기 때문에 줄 높이는 고정된다. 그리고 응답이 오면 이 스켈레톤 UI를 실제 숫자로 교체한다. 응답이 끝내 오지 않으면(`catch`) 그 칩만 감춰서, 빈 스켈레톤 UI가 계속 반짝이지 않게 했다.

```ts
fetch(`https://abacus.../${mode}/injoy-rjstony/${key}`)
  .then((res) => res.json())
  .then((data) => { value.textContent = data.value.toLocaleString('ko-KR'); }) // [!code highlight]
  .catch(() => { el.hidden = true; }); // 카운터가 죽으면 그 칩만 조용히 감춘다
```

이렇게 바꾸고 나니 숫자가 늦게 오더라도 **화면이 출렁이지 않고**, 글에 들어오자마자 조회수가 제자리에 표시된다. 홈 목록에서 조회수를 올리지 않는 것도 같은 컴포넌트가 처리한다. `mode`를 `hit`(올리고 조회)이 아니라 `get`(조회만)으로 두면, 둘러보는 것만으로는 숫자가 부풀지 않는다.

태그라인도 "즐거움 안에서"로 바꾸었다. In joy, Injoy다.

## 조용히 묻혀 있던 것들

눈에 잘 띄지 않아서 그대로 묻혀 있던 문제도 두 가지를 고쳤다.

첫 번째는 그래프의 태그 점선이다. 태그로 잇는 점선이 너무 연해서 거의 보이지 않았다(정말 있긴 한 걸까 싶을 만큼). 원인은 태그 점선만 거의 흰색에 가까운 토큰을 따로 사용하고 있었던 것이다. 태그 점선이 사용하던 `colors.border`는 거의 흰색이어서, 흰 배경 위에서는 있으나 마나였다. 그래서 이것을 한 단계 진한 `colors.muted`로 바꾸고(`faint`면 무조건 muted), 투명도도 0.55에서 0.7로 조금 높였다.

```ts src/pages/graph.astro
const faint = isTag || isMention; // 태그·언급 연결선은 약하게 그린다
const stroke = isTag ? colors.border : isMention ? colors.muted : colors.edge[e.type]; // [!code --]
const stroke = faint ? colors.muted : colors.edge[e.type] || colors.accent; // [!code ++]
const alpha = base * (faint ? 0.55 : 0.95); // [!code --]
const alpha = base * (faint ? 0.7 : 0.95); // [!code ++]
```

색 계열은 회색 그대로 두고, 흰 배경에서도 이어져 있다는 것이 보일 만큼만 진하게 했다. 이제는 흐릿하게라도 이어진 것이 보인다. 다만 이 투명도는 [[polish-round-5|나중에 한 번 더 조정하게 된다]].

두 번째는 모바일의 목차다. 위에 있던 목차 카드는 스크롤하면 사라졌기 때문에, 지금 어디를 읽고 있는지 알 수 없었다. 그래서 오른쪽 가장자리에 세로 라인을 띄워서, 지금 읽고 있는 섹션을 진하게 표시하도록 했다. 라인을 누르면 그 자리로 이동하고, 본문은 가리지 않는다.

## 남은 것

발행은 예전 그대로다. 카테고리 하나를 추가한 것만으로도 글이 한결 정리되어 보여서, 글이 쌓이는 재미가 조금 더 생겼다. 🌱
