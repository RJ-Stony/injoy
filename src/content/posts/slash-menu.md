[[wysiwyg-editor|지난 글]]에서 에디터를 위지윅 방식으로 바꾸고는, 끝에 숙제 같지 않은 숙제를 두 개 적어두었다. 하나는 슬래시(`/`) 메뉴가 아직 없다는 것이었고, 다른 하나는 콜아웃 맨 앞에서 글자를 지우면 숨은 마커가 동시에 지워져서 평범한 인용으로 바뀐다는 것이었다. 이번에는 이 두 가지를 손보게 되었다.

## 슬래시 한 번이면

이제 빈 줄에서 `/`를 입력하면 작은 메뉴가 나타난다. 메뉴에는 제목, 인용, 콜아웃, 표, 목록, 체크리스트, 구분선, 코드 블록, 수식, 각주, 다이어그램처럼 툴바에 있는 기능들이 들어 있다. 이어서 글자를 입력하면 목록이 좁혀지고, 방향키로 항목을 고른 뒤 엔터를 누르면 그 자리에 해당 블록이 삽입된다.

> [!NOTE]
> 슬래시 메뉴는 PC에서도, 모바일에서도 되지만, 모바일에서는 예전처럼 삽입 툴바 기능을 쓰는 게 조금 더 낫다. 좁은 화면에서 작은 팝업을 정확히 누르게 하느니 **큼직한 버튼**이 낫다고 본다.

## 삽입하는 코드는 따로 만들지 않았다

슬래시 메뉴로 블록을 추가하는 방식은 툴바와 똑같이 두었다. 슬래시로 고른 항목은 결국 툴바의 삽입 함수로 전달된다. 메뉴는 마크다운 조각을 만들어 건넬 뿐, 삽입하는 로직을 따로 가지지 않는다. 그래야 툴바와 슬래시가 서로 어긋나지 않을 것 같았다.

항목을 고르면 `choose` 함수가 실행된다. 이 함수는 슬래시와 그 뒤에 입력한 글자를 선택 상태로 만들어서 한 번의 트랜잭션으로 블록에 치환되게 한 다음, `onInsert(item.md)`로 `item.md`라는 마크다운 조각을 넘긴다. 이 `onInsert`는 툴바가 블록을 넣을 때 쓰는 바로 그 함수이다. 삽입하는 곳이 한 군데뿐이기 때문에, 툴바에서 잘 들어가는 블록은 슬래시에서도 똑같이 들어간다.

```ts src/scripts/milkdown-editor.ts
const choose = (view, item) => {
  const to = view.state.selection.from;
  // '/질의' 글자를 선택 상태로 만들어 한 트랜잭션에 치환되게 한다
  if (to > from) {
    view.dispatch(view.state.tr.setSelection(
      TextSelection.create(view.state.doc, from, to)));
  }
  close();
  onInsert(item.md); // [!code highlight]
  view.focus();
};
```

이렇게 삽입 경로를 하나로 맞추고 나서도, 슬래시라는 글자 자체가 문제를 일으키는 경우가 있었다.

## URL 속의 슬래시는 그냥 두기

막상 연결하고 보니 성가신 경우가 있었다. 본문에 `https://`를 적을 때 그 슬래시마다 메뉴가 나타나면 곤란하다. 그래서 `/`는 줄의 맨 앞이거나 공백 바로 뒤일 때만 메뉴를 열도록 했다. URL 안의 슬래시는 앞에 글자가 붙어 있기 때문에 메뉴를 열지 않고 지나간다.

이 조건은 정규식(문자열에서 패턴을 찾는 규칙) 한 줄로 판단한다. 커서 앞의 텍스트에서 `/`가 **줄 맨 앞이거나 공백 바로 뒤일 때만** 찾고, 그 뒤에 이어서 입력한 글자(검색어)를 함께 잡는다.

```ts src/scripts/milkdown-editor.ts
// 커서 앞 텍스트(before)에서 '/명령어'를 줄머리나 공백 뒤에서만 찾는다
const m = before.match(/(?:^|\s)\/([^\s/]*)$/);
if (!m) return null; // 못 찾으면 메뉴를 열지 않는다
```

`https://`의 슬래시는 앞에 `s`나 `:`가 붙어 있어 이 조건에 걸리지 않으므로, 메뉴도 열리지 않는다. 슬래시를 걸러 내고 나니, 이번에는 글자를 입력하는 도중의 동작이 남아 있었다.

## 한글을 조합하는 중에는 비켜서기

한글은 자음과 모음을 합쳐서 글자 하나를 만드는 조합 단계를 거친다. 이 단계에서 메뉴가 키를 가로채면 문제가 생긴다.

> [!WARNING]
> 한글을 조합하는 중에는 메뉴가 방향키나 엔터를 가로채지 않게 했다. 이걸 빠뜨리면 글자를 만드는 도중에 메뉴가 끼어들어서 조합이 깨질 수도 있다. 콜아웃도 같은 이유로 한글 조합 중에는 나타나지 않도록 방지했다.

그래서 메뉴의 키가 처리되는 맨 앞에서, 한글 조합 중이면 `false`를 반환하도록 했다. `return false`는 '이 키는 내가 처리하지 않으니 그대로 보내라'는 뜻이다. 이렇게 하면 ㄱ·ㅏ·ㅂ을 합쳐 '갑'을 만드는 도중에도 메뉴가 방향키나 엔터 때문에 조합을 깨뜨릴 일이 없다.

```ts src/scripts/milkdown-editor.ts
handleKeyDown: (view, event) => {
  if (!open) return false;
  if (view.composing || event.isComposing) return false; // [!code highlight]
  // 여기부터 방향키·Enter·Esc 처리
}
```

슬래시 메뉴는 이렇게 정리되었고, 남은 것은 콜아웃이었다.

## 콜아웃 머리에서 글자를 지울 때

콜아웃은 화면에 박스로 보이지만, 속에는 `[!NOTE]` 같은 **숨은 마커**가 들어 있다. 예전에는 박스 맨 앞에서 글자를 지우면 이 마커가 함께 지워져서, 발행할 때 평범한 인용으로 바뀌었다. 이제는 박스 머리에서 지우는 동작을 감지해서, 마커가 일부만 지워지는 대신 통째로 지우고 평범한 인용으로 깔끔하게 풀리도록 했다.

이 처리는 콜아웃의 앞부분에서만 작동해야 한다. 아래의 `handleKeyDown`은 커서가 콜아웃 머리에 있을 때만 머리를 통째로 지워 콜아웃을 해제하고, 그 밖의 모든 경우에는 마지막 `return false`로 키를 그대로 넘긴다. 마커가 깨질 수 있는 앞부분 이외의 자리는 건드리지 않기 위해서이다.

```ts src/scripts/milkdown-editor.ts
handleKeyDown(view, event) {
  if (event.key !== 'Backspace' && event.key !== 'Delete') return false;
  if (view.composing || event.isComposing) return false; // 조합 중엔 손대지 않는다
  // 커서가 콜아웃 머리에 있을 때만 머리를 통째로 지워 콜아웃을 해제한다
  if (eatsBack || eatsFwd) return drop(removeFrom, removeTo); // [!code highlight]
  return false; // [!code highlight]
}
```

두 가지를 모두 고쳤지만, 이런 코드는 빌드가 통과했다는 사실만으로는 믿을 수 없었다.

## 여러 번 돌린 리뷰

키 입력을 가로채는 코드는 문제가 있어도 빌드가 어느 쪽이든 멀쩡히 통과한다. 그래서 이런 부분일수록 [[wysiwyg-editor|위지윅 에디터를 만들 때]]처럼 여러 시선으로 들여다보는 적대적인 리뷰를 한 번 더 실행했다. 슬래시는 한 번, 콜아웃은 세 번을 거치고 나서야 본 코드에 합칠 수 있었다.

## 결론

글을 작성하는 화면은 또 한 결 편해졌다. 슬래시로 추가하고, 보이는 대로 고치고, 발행은 예전 그대로다. 각 블록이 실제로 어떻게 보이는지는 [[markdown-styleguide|문법을 모아 둔 글]]에 정리해 두었다. 결국 이번에도 글쓰기를 가로막는 마찰을 한껏 더 줄였다. 🌱
