이 블로그의 글쓰기 과정은 한 문장으로 요약된다.

> 마크다운 파일을 하나 작성하면, 바로 글이 블로그에 올라간다.

추가적인 설정을 건드릴 필요도, 어디 중간에 글을 등록할 필요도 없다. 이 글은 그 과정을 단계별로
설명하는 가이드 글이다. 미래의 내가 잊었을 때 다시 읽기 위해 써보려고 한다.

## 1. 파일 만들기

`src/content/posts/` 폴더에 `.md` 파일을 만든다. **파일명이 곧 블로그의 주소가 된다.**

```text
src/content/posts/my-first-post.md  →  /posts/my-first-post/
```

한글 파일명도 동작은 하지만, URL이 길게 인코딩되기 때문에 영문 소문자와 하이픈을 같이 사용하는 것을 권장한다.
컴포넌트를 본문에 넣고 싶다면 `.mdx` 확장자를 쓰면 된다.

직접 만들기 귀찮다면 명령어 한 줄로 시작할 수 있다.

```bash
npm run new -- my-first-post "첫 글입니다"
```

frontmatter(글 머리에 적는 글의 메타 정보)가 채워진 파일이 `draft: true` 상태로 생성된다. 초안을 다듬은 뒤
`draft: false`로 바꾸면 글이 올라간다.

## 2. frontmatter 채우기

파일 맨 위에 글의 메타 정보를 적는다. `---` 사이의 영역이 frontmatter다.

```yaml
---
title: "글의 제목"
description: "목록/검색/공유 미리보기에 쓰이는 한 줄 요약"
pubDate: 2026-06-10
category: "블로그"
tags: ["astro", "블로그"]
draft: false
---
```

| 필드            | 필수 | 설명                                                 |
| ------------- | -- | -------------------------------------------------- |
| `title`       | ✅  | 글 제목                                               |
| `description` | ✅  | 글의 한 줄 요약. 홈페이지와 **OG 태그**(링크 공유 미리보기에 보이는 것들)에 쓰임 |
| `pubDate`     | ✅  | 발행일 (`YYYY-MM-DD`)                                 |
| `category`    | ✅  | 카테고리 라벨 (예: 블로그, 글쓰기, 회고)                          |
| `tags`        | 선택 | 태그 배열. `/tags/태그명/` 페이지가 자동 생성됨                    |
| `draft`       | 선택 | `true`면 프로덕션 빌드에서 제외 (기본값 `false`)                 |
| `cover`       | 선택 | 대표 이미지 경로                                          |

스키마(글이 갖춰야 할 데이터의 틀)는 `src/content.config.ts`에 zod(값들이 규칙에 맞는지 검사하는 도구)로 정의되어 있어서, 필수적인 필드가 빠지면
빌드가 에러와 함께 실패하게 된다.

## 3. 본문 작성하기

frontmatter 아래부터는 Notion에서 쓰듯 마크다운으로 쓰면 된다. 제목(`##`), 목록, 인용,
표, 체크박스 같은 **GFM 문법**(GitHub Flavored Markdown; 깃허브식 마크다운 문법)에 더해 콜아웃(`> [!NOTE]`), 각주(`[^1]`),
수식(`$E=mc^2$`), 다이어그램(` ```mermaid `), 이모지 숏코드(`:rocket:`),
이미지 캡션, 코드 줄 강조/diff 표기(`// [!code highlight]`)까지 지원한다.
어떻게 보이는지는 [[markdown-styleguide|이 글]]에서 확인할 수 있다.

다른 글을 잇고 싶을 때는 `[[슬러그]]`(슬러그는 글의 주소 이름)라고만 쓰면 된다. 제목이 자동으로 들어가고,
[그래프](/graph/)에 "언급" 연결도 자동으로 생긴다. 더 강한 관계(확장/뒷받침/반박 등)는
글쓰기 화면의 **연결(그래프)** 메뉴에서 종류를 골라 수정할 수 있다.

코드블록은 언어를 지정하면 자동으로 **하이라이트**되고, 복사 버튼이 추가된다.

```js
// 언어를 지정하면 이렇게 하이라이트된다
const greet = (name) => `안녕하세요, ${name}님!`;
console.log(greet('Injoy'));
```

`##`(h2)와 `###`(h3) 제목은 **글 상단의 목차**에 자동으로 수집된다. 그러니 글의 뼈대를
제목으로 먼저 잡고 살을 붙이면 목차가 바로 생기게 된다 !

## 4. 초안은 draft로

아직 공개하고 싶지 않은 글은 frontmatter에 `draft: true`를 넣는다.

```yaml
draft: true   # 프로덕션 빌드에서 제외된다
```

`npm run dev`로 띄운 로컬 미리보기에서는 보이지만, `npm run build`(글들을 모아 실제 블로그로 만들어 내는 과정)로 만든 배포본에는
포함되지 않는다. 글을 다듬는 동안 커밋해 두어도 안전하다.

## 5. 확인하고 발행하기

세 명령이면 끝난다. 쓰는 동안 미리 보고, 실제 발행본을 만들고, 그 결과를 한 번 더 확인한다.

```bash
npm run dev       # http://localhost:4321 에서 미리보기
npm run build     # 프로덕션 빌드
npm run preview   # 빌드 결과 확인
```

로컬에서 확인했다면, 커밋하고 GitHub에 푸시한다. Vercel이나 GitHub Pages에 연결되어 있다면(현재는 **GitHub Pages**에 배포) 푸시하는 행위가 곧 글이 올라가는 과정으로 이어진다. RSS(`/rss.xml`)도 빌드할 때마다 자동으로 갱신되니
따로 신경 쓸 것이 없다.

---

정리하면 **파일 하나, frontmatter, GitHub로 push.** 글쓰기를 방해하는 마찰을 줄이는 데 이 블로그 구조의 거의 전부를 걸었다. 이제 쓰는 일만 남았다.
