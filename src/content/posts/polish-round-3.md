이 블로그는 처음부터 [[welcome|미래의 나]]에게 보내는 기록이었다. 몇 달 뒤 같은 문제 앞에서 헤맬 나를 위해, 삽질을 그때그때 적어 두는 곳. 그런데 얼마 전, 코드를 잘 모르는 사람이 글을 읽고 솔직한 감상을 건넸다. 흐름은 따라오겠는데 *중간중간 모르는 단어에서 턱턱 막힌다*는 것이었다. frontmatter, 직렬화, 정규식 같은 말이 설명 없이 지나가고, 코드 블록을 만나면 그냥 건너뛰게 된다고 했다.

생각해 보니 이 블로그가 나만 읽을 공간은 아니었다. 검색하다 우연히 들어온 누군가도 독자다. 그래서 이번엔 *그 사람*을 염두에 두고 글과 화면을 다시 손봤다.

## 전문 용어 옆에 작은 풀이를 달았다

가장 크게 바꾼 건 단어다. 전문 용어가 처음 나오는 자리에 **짧은 한국어 풀이를 괄호로** 달았다. 영어 단어 자체는 그대로 둔다. 굳어진 말을 어설프게 토박이말로 바꾸면 오히려 더 낯설어지니, 뜻만 곁들이는 쪽을 택했다.

예전엔 이렇게 썼다.

> 파일 맨 위에 frontmatter를 적는다.

지금은 이렇게 쓴다.

> 파일 맨 위에 frontmatter(글 머리에 적는 글 정보)를 적는다.

한 번 풀어 준 말은 같은 글 안에서 다시 풀지 않는다. 풀이가 너무 잦으면 그것대로 읽는 흐름을 끊기 때문이다. [[how-to-write]]와 [[wysiwyg-editor]]처럼 용어가 빽빽한 글부터 손봤고, [[markdown-styleguide]]같이 원래 개발자가 보는 글은 가볍게만 짚었다.

## 코드 앞뒤에 "결국 무엇을 한다" 한 문장

두 번째는 코드다. 코드 자체는 못 읽어도, **그 코드가 결국 무엇을 하는지 한 문장**만 곁에 있으면 건너뛰고도 흐름을 잃지 않는다. 사실 이 블로그는 그 버릇을 어느 정도 지키고 있었다. [[polish-round]]에 적은 *"강조한 한 줄이 판단의 전부다"* 와 같은 문장이 그랬다. 이번엔 그게 빠진 코드들을 메웠다. 코드를 못 읽는 사람은 그 한 문장만 읽고 지나가면 된다.

이 결을 처음 잡은 건 [[polish-round-2|지난 회차]] 즈음이었다. 코드 설명이 번역투에 추상적이라 더 어렵다는 지적을 받고, 보이지 않는 동작을 *눈에 보이는 말*로 다시 쓰기 시작했다. 이번엔 그걸 용어와 코드 양쪽으로 넓힌 셈이다.

## 강조가 화면 끝에서 잘리고 있었다

글을 다듬다 보니 화면 쪽 버그도 둘 눈에 들어왔다. 하나는 휴대폰에서 코드 한 줄을 강조했을 때다. 강조한 줄이 길어 가로로 넘치면, 옆으로 밀어 봐도 색이 화면 끝에서 뚝 끊겼다. 강조 배경이 줄 끝까지 안 따라오고 *보이는 만큼만* 칠해진 것이다.

원인은 한 줄이었다. 강조 배경의 너비를 "100%"로 줬는데, 이 100%가 코드 전체 너비가 아니라 *화면에 보이는 너비*로 계산되고 있었다.

```css src/styles/global.css
.prose pre code {
  display: block;          /* [!code ++] */
  min-width: max-content;  /* [!code ++] */
}
```

추가된 두 줄이 전부다. 코드 영역을 `max-content`(내용 전체 너비만큼 늘리라는 뜻)로 펴 주니, 강조의 기준이 *화면 너비*에서 *코드 전체 너비*로 바뀐다. 그러자 옆으로 밀어도 강조가 줄 끝까지 따라온다. 마침 이 글에도 코드가 있으니, 휴대폰에서 위 코드 블록을 옆으로 밀어 보면 강조가 어디까지 칠해지는지 바로 보인다.

## 만듦새가 거짓말을 하고 있었다

다른 하나는 글 아래 '이 글의 만듦새' 쪽이다. 거기 '수정' 줄이 늘 이렇게 떴다.

> 처음 발행한 뒤 한 번 다듬었어요.

문제는, 몇 번을 고쳐도 언제나 "한 번"이었다는 것이다. 이 블로그는 글을 고친 *횟수*를 따로 세어 두지 않는다. 가진 건 처음 낸 날짜와 마지막으로 고친 날짜뿐인데, "한 번"이라는 숫자는 어디에도 근거가 없었다. 솔직함을 내세우는 블로그가 슬그머니 거짓말을 하고 있던 셈이다.

횟수를 진짜로 세려면 글의 수정 이력을 빌드할 때 추가해야 하는데, 배보다 배꼽이 커지는 일이라 그만두었다. 대신 *가진 데이터*만 솔직하게 보여 주기로 했다.

> 2026년 6월 13일에 처음 내고, 6월 21일까지 다듬었어요.

없는 숫자를 지어내느니, 처음 낸 날과 마지막으로 손본 날 사이의 *기간*을 보여 주는 편이 정직하다고 생각했다.

## 남은 것

[[welcome|첫 글]]을 비롯해 손대지 않은 글도 있다. 거기선 어려운 말이 거의 없어, 굳이 풀이를 끼워 넣으면 오히려 군더더기가 된다. 모든 글을 똑같이 다듬는 게 목표가 아니라, *막히는 자리*만 풀어 주는 게 목표다.

제목에서 콜론을 떼고, 코드 설명을 쉽게 풀고, 용어에 풀이를 달고. 돌아보면 요즘 한 일은 다 한 방향을 본다. **읽는 사람과 글의 마찰을 줄이는 것.** 독자들이 늘었으니, 글도 그만큼 친절해져야 할 것 같다. 천천히, 그러나 꾸준히 계속 다듬어 보겠다. 🌱
