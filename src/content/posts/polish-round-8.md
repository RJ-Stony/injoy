[[polish-round-7|지난 글]]에서는 그래프를 자유롭게 움직일 수 있도록 했다. 이번에는 글 자체가 아니라 글의 앞과 뒤를 손보게 되었다. 발행하고 나서 멍하니 기다리던 시간을 없애고, 글을 다 읽고 난 뒤의 빈자리를 채우는 작업이었다.

## 발행은 사실 이미 끝나 있었다

글을 작성하는 화면에서 발행을 누르면, 글이 사이트에 올라갈 때까지 1분쯤 멍하니 기다려야 했다. 그동안 화면에는 "배포 중…"이라는 문구만 돌고 있었다.

그런데 생각해 보니 **커밋(GitHub에 글을 올리는 것)이 곧 발행**으로 이어지는 것이었다. 그 뒤의 1분은 배포(올린 글을 사이트 화면으로 바꾸는 빌드)가 실행되는 시간일 뿐이어서, 내가 화면을 붙잡고 기다릴 이유가 없었다. 그래서 커밋이 끝나면 곧바로 발행되었다고 알리고, 배포가 끝났는지는 뒤에서 확인하도록 순서를 바꾸었다.

```ts src/pages/write.astro
// 예전: 커밋한 뒤, 배포가 끝날 때까지 화면을 붙잡고 기다렸다
status.textContent = '배포를 기다리는 중…'; // [!code --]
const ok = await waitForDeploy(sha); // [!code --]
// 이제: 커밋되면 바로 끝났다고 알린다. 배포 확인은 뒤에서 알아서 한다.
status.textContent = '✓ 발행됐어요'; // [!code ++]
trackDeploy(sha); // 배포는 백그라운드로 확인하고, 끝나면 표시만 바꾼다 // [!code ++]
```

이제 발행을 누르면 곧장 "발행됐어요"라는 문구가 나타나고, 에디터의 잠금도 바로 풀린다. 글이 사이트에 반영되었는지는 작은 표시가 뒤에서 알려 준다. 그렇게 멍하니 기다리던 1분이 사라졌다.

## 댓글을 받기로 했다

다음은 글을 다 읽고 난 뒤의 빈자리였다. 그동안 이 블로그의 글은 일방통행이었다. 그래서 글 아래에 댓글을 달 수 있도록 giscus(GitHub의 토론 기능을 이용하는 댓글 툴)를 연결했다.

마음에 드는 점은, 이 블로그가 정적 사이트(미리 만들어 둔 파일만 내보내는 방식)인데도 **서버도 시크릿 키도 없이** 댓글을 달 수 있다는 것이다. 댓글은 GitHub에 쌓이고, GitHub 계정으로 로그인하면 누구나 작성할 수 있다. 화면을 밝게 또는 어둡게 바꾸면 댓글창도 그 테마에 맞추어 함께 바뀐다.

## 시리즈로 묶고, 접어 두기

블로그를 다듬는 글이 어느새 8편이 되었다. 순서는 이미 잡혀 있지만, 나중에 이런 시리즈가 더 많이 생길 수도 있다. 그래서 이 글들을 **하나의 시리즈로 묶어서**, 글 아래에서 1편부터 차례로 보여주도록 했다. 지금 읽고 있는 글이 몇 번째인지도 함께 보여준다.

다만 글 아래에는 이미 연결된 글과 만듦새처럼 들어가야 할 것이 많았다. 그래서 시리즈는 평소에는 접어 두고, 궁금할 때만 펼쳐 보도록 했다.

## 작은 것 하나 더

코드 블록의 복사 버튼도 조금 고쳤다. 고친 흔적을 보여주는 코드(diff)에서는 **지운 줄을 제외하고 남는 코드만** 복사되도록 했다. 예전에는 지운 줄까지 통째로 복사되었기 때문에, 그대로 붙여 넣으면 코드가 어긋났다.

## 남은 것

글을 쓰는 쪽(발행)과 읽는 쪽(댓글, 시리즈)을 한 번에 손보았다. 쓰면서는 덜 기다리고, 읽고 나서는 한마디를 건넬 수 있게 되었다. 댓글이 어떻게 쌓일지는 두고 보아야 알 것 같다. <span class="tossface">🌱</span>
