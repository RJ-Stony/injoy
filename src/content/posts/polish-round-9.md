글이 13편이 되었다. 많다고 할 수는 없지만, 홈을 열면 글이 아래로 계속 이어졌다. 게다가 '블로그 다듬기 기록'처럼 한 줄기로 묶고 싶은 글들이 피드 여기저기에 흩어져 있었다. 그래서 글이 더 쌓이기 전에, 쌓인 글을 어떻게 보여줄지부터 손보기로 했다.

## 같은 시리즈는 폴더 하나로

가장 신경 쓰이는 것은 시리즈였다. 같은 흐름의 글 8편(지금은 9편)이 최신 글 사이사이에 끼어서 목록을 길게 늘이고 있었다. 그래서 **시리즈로 묶인 글은 폴더 하나로 접어** 두고, 폴더를 누르면 그 자리에서 안에 있는 글들이 펼쳐지도록 했다.

이를 위해 먼저 글을 '시리즈에 속한 글'과 '낱개 글'로 나누었다. 시리즈에 속한 글은 폴더로 보내고, 나머지 글만 목록에 남긴다. 아래의 함수는 같은 `series`(글 머리에 적는 묶음 이름) 값을 가진 글을 모으는데, 그런 글이 2편 이상일 때만 하나의 폴더로 만든다.

```ts src/utils/post.ts
export async function getSeriesGroups() {
  const posts = await getPublishedPosts();
  const map = new Map();
  for (const p of posts) {
    if (!p.data.series) continue; // 시리즈 없는 글은 건너뛴다
    if (!map.has(p.data.series)) map.set(p.data.series, []);
    map.get(p.data.series).push(p);
  }
  return [...map.entries()]
    .filter(([, ps]) => ps.length > 1) // [!code highlight]
    .map(([series, ps]) => ({ series, posts: ps }));
}
```

폴더는 닫힌 상태로 두고, 닫혀 있을 때는 가장 최근 글의 제목을 옆에 작게 보여준다. 폴더를 열면 안에 있는 글이 읽는 순서대로 나오고, 읽는 시간과 조회수도 함께 보인다. 폴더라는 구조로 생각해 보니, 글이 폴더 안에 담긴 파일처럼 느껴졌다.

## 목록은 열 개씩 끊어서

폴더로 묶더라도 글은 계속 늘어난다. 그래서 홈, 카테고리, 태그 화면 모두 **처음 열 개만 보여주고 나머지는 다음 페이지로** 넘기도록 했다. 이런 방식을 페이지네이션(긴 목록을 여러 쪽으로 끊어 보여주는 것)이라고 한다. Astro에는 페이지네이션을 만들어 주는 기능이 있어서, 글 목록을 넘겨주기만 하면 알아서 페이지를 나눈다.

```ts src/pages/[...page].astro
export async function getStaticPaths({ paginate }) {
  const posts = await getStandalonePosts();
  return paginate(posts, { pageSize: 10 }); // [!code highlight]
}
```

정적 사이트이기 때문에 페이지마다 고유한 주소가 생긴다. 1쪽은 `/`, 2쪽은 `/2`와 같은 식이다. 그래서 검색 엔진이 모든 쪽을 따라올 수 있고, 화면도 가벼워진다. 지금은 글이 적어서 아직 2쪽이 없지만, 글이 늘어나면 자연스럽게 나뉠 것이다.

## 발행하는 순간을 조금 더 즐겁게

[[polish-round-8|지난 글]]에서 발행한 뒤에 멍하니 기다리던 시간을 없앴다. 이번에는 그 끝을 조금 더 즐겁게 만들었다. 배포가 끝나는 순간, 돌고 있던 원이 체크 표시로 바뀌면서 살짝 튀어 오르고 🌱이 함께 피어난다. 글을 쓰는 사람에게 보내는 작은 축하의 메시지이다. 움직임을 줄이는 설정을 켜 둔 사람에게는 모션 없이 조용히 바뀌도록 했다.

## 그 김에 다듬은 것들

- **캡션** - 이제 에디터에서 이미지 캡션(그림 아래에 붙는 설명)을 직접 적을 수 있다. 사실 발행하는 쪽에서는 진작부터 캡션을 렌더링할 수 있었는데, 정작 글을 작성하는 화면에 입력칸이 없었다.

- **댓글** - 댓글창의 색과 모서리를 블로그의 톤에 맞추었다. 댓글은 여전히 GitHub 토론에 의존하고 있어서 구조까지는 바꾸지 못하지만, 적어도 블로그와 따로 노는 것처럼 보이지는 않는다.

- **좀 더 부드럽게** - 폴더와 시리즈 내비게이션이 펼쳐지고 접힐 때, 뚝뚝 끊기지 않고 부드럽게 움직이도록 했다.

마지막 항목은 의외로 한 줄에 가까운 수정이었다. `::details-content`(펼쳐지는 영역만 따로 가리키는 새 CSS 선택자)에, 높이가 '자동'인 상태까지 부드럽게 이어지도록 해 주는 설정을 함께 적으면 된다.

```css
details::details-content {
  block-size: 0; /* 닫히면 높이 0 */
  overflow: clip;
  transition: block-size 0.28s ease, content-visibility 0.28s allow-discrete; /* [!code highlight] */
}
details[open]::details-content { block-size: auto; } /* 열리면 실제 높이로 */
```

덕분에 자바스크립트 없이도 열고 닫는 움직임이 매끄러워졌다. 아직 이 기능을 지원하지 않는 브라우저에서는 예전처럼 즉시 열린다.

## 남은 것

인기순 정렬은 아직 보고 있는 페이지 안에서만 순서를 다시 정한다. 조회수는 사이트를 빌드하는 시점에는 없고, 화면에서야 불러오기 때문이다. 이 문제는 글이 훨씬 많아지면 그때 다시 살펴볼 예정이다. <u>쌓이는 것을 미리 겁내기보다, 쌓일 때마다 한 칸씩 정리하는 편이 나에게는 맞는 것 같다.</u> 🌱
