글이 하나둘 쌓이면서 그래프(글을 점으로, 글 사이 연결을 선으로 그린 화면)가 점점 빽빽해졌다. 그러다 어느 순간, 가장자리의 점들이 화면 밖으로 잘려 나가기 시작했다. [[polish-round|예전엔]] 이 그래프가 멈추질 않아 고생했는데, 이번엔 점들이 자꾸 밖으로 도망가는 게 문제였다.

## 점이 화면 밖으로 나가던 이유

그래프의 점들은 서로 밀고 당기며 스스로 자리를 잡는다(force 시뮬레이션(점들이 용수철처럼 밀고 당겨 저절로 배치되는 계산)). 그런데 예전엔 점의 *중심*만 화면 안에 가두고 있었다. 점에는 원의 반지름이 있고, 그 아래엔 글 제목(라벨)이 붙는다. 중심은 안에 있어도 원과 글자는 가장자리에서 잘려 나갔다. 글이 많아질수록 점들이 가장자리로 밀려나 더 심해졌다.

그래서 발상을 바꿔야 풀렸다. 점을 화면에 맞춰 가두는 대신, **점 전체가 들어올 만큼 화면을 줄여서 맞추기로** 했다. 글이 몇 개든 한 화면에 다 담길 수 있게 한 것이다.

## 손가락으로 옮기고, 버튼으로 확대

화면을 자유롭게 다루는 김에, 그래프를 직접 만질 수 있게 했다. 빈 곳을 끌면 그래프가 따라 움직이고, 점을 끌면 그 점만 옮겨진다. 확대는 캔버스(그림을 그리는 화면 영역) 오른쪽 아래의 +, − 버튼으로 한다.

처음엔 확대를 두 손가락으로 오므렸다 펴거나(휴대폰) Ctrl을 누른 채 굴리는(컴퓨터) 방식만 뒀다. 그런데 그건 아는 사람만 쓴다. 그래서 그냥 보자마자 누를 수 있는 버튼을 더했다. 모바일에서도 똑같이 버튼만 누르면 되니, 손가락 동작을 몰라도 된다.

## 미리보기가 못 보여 준 흔들림

여기서 한 번 또 데었다. 새로 만든 그래프가 내 미리보기(고친 걸 바로 띄워 보는 화면)에선 멀쩡했는데, 막상 배포하니 그래프가 마구 요동쳤다.

원인은 이랬다. 점들을 화면에 맞추는 계산을 **매 프레임(화면을 다시 그리는 매 순간)** 돌리고 있었다. 점들이 아직 자리를 잡느라 계속 움직이는데, 그때마다 화면도 같이 따라서 확대·이동을 하니, 점과 화면이 서로를 쫓아다니며 전체가 출렁인 것이다.

```ts
const loop = () => {
  tick();        // 점들을 한 칸씩 움직이고
  fitToBbox(); // [!code --]
  draw();        // 화면에 그린다
  // 점들이 다 멈췄을 때(정착), 딱 한 번만 맞춘다
  if (pendingFit) { // [!code ++]
    fitToBbox(); // [!code ++]
    pendingFit = false; // [!code ++]
  } // [!code ++]
};
```

결국, 매 프레임이 아니라 점들이 다 멈췄을 때 한 번만 화면에 맞춘다. 움직이는 동안에는 처음 잡아 둔 화면을 그대로 쓰고, 점은 정해진 상자 안에서만 움직이게 가둬 두니 밖으로 샐 일이 없다.

> 더 뼈아픈 건, 이 버그를 미리보기로는 끝내 못 봤다는 점이다.

코드 상 미리보기는 그래프처럼 움직이는 화면에서 그 *움직임*을 거의 돌리지 않는다. 그래서 멈춘 그림만 보고 "괜찮네" 하고 넘긴 거다. 움직여 봐야 드러나는 버그는 도구가 아니라 코드로 따져야 잡힌다는 걸 다시 배웠다.

## 검색 버튼이 위로 튀던 이유

같은 결의 조용한 버그(눈에 잘 안 띄는 버그)가 검색에도 있었다. '결과 더 보기'를 처음 누르면 화면이 갑자기 맨 위로 튀어 올랐다.

범인은 포커스(화면이 지금 주목하고 있는 자리)였다. 마지막 글까지 다 불러오면 '결과 더 보기' 버튼은 사라진다. 그런데 버튼이 사라지는 순간, 거기 가 있던 포커스가 갈 곳을 잃고 문서 맨 위로 올라간다. 그러면 브라우저는 친절하게도 그 자리로 화면을 스르륵 올려 버린다.

```ts
if (done) {
  // 버튼이 사라지기 전에, 포커스를 방금 뜬 결과로 옮긴다
  firstNew.querySelector('.sr-title')?.focus({ preventScroll: true }); // [!code ++]
  moreBtn.hidden = true;
}
```

결국 사라질 버튼을 포커스가 따라가지 않도록, 미리 새로 뜬 결과로 옮겨 둔다. preventScroll은 "옮기되 화면은 움직이지 말라"는 뜻이다. 이러니 더 보기를 눌러도 보던 자리에 그대로 머문다.

## 남은 것

이번엔 새 기능보다, 그래프는 손에 더 익게, 검색은 덜 튀게 만들었다.

배운 건 따로 있다. *보기엔 멀쩡한데 움직여 보면 무너지는* 종류의 버그는, 화면을 한 번 보고 넘기면 절대 안 잡힌다. 움직이는 화면일수록 더 의심하며 봐야 할 것 같다. <span class="tossface">🌱</span>
