글이 하나둘 쌓이면서 그래프(글을 점으로, 글 사이 연결을 선으로 그린 화면)가 점점 빽빽해졌다. 그러다 어느 순간부터 가장자리에 있는 노드들이 화면 밖으로 잘려 나가기 시작했다. [[polish-round|예전에는]] 이 그래프가 멈추지 않아서 고생했는데, 이번에는 노드들이 자꾸 화면 밖으로 나가는 것이 문제였다.

## 노드가 화면 밖으로 나가던 이유

그래프의 노드들은 force 시뮬레이션(노드들이 용수철처럼 밀고 당겨 저절로 배치되는 계산)에 따라 서로 밀고 당기면서 스스로 자리를 잡는다. 그런데 예전에는 노드의 중심만 화면 안에 들어오도록 제한하고 있었다. 노드에는 원의 반지름이 있고, 그 아래에는 글 제목(라벨)이 붙는다. 그래서 중심은 화면 안에 있더라도 원과 글자는 가장자리에서 잘려 나갔다. 글이 많아질수록 노드들이 가장자리로 밀려나기 때문에, 이 문제는 점점 더 심해졌다.

이 문제는 발상을 바꾸고 나서야 해결되었다. 노드를 화면에 맞추어 가두는 대신, **노드 전체가 들어올 만큼 화면을 줄여서 맞추기로** 했다. 글이 몇 개이든 한 화면에 모두 담기도록 한 것이다.

## 손가락으로 옮기고, 버튼으로 확대

화면을 자유롭게 다룰 수 있게 된 김에, 그래프를 직접 움직일 수 있도록 했다. 빈 곳을 끌면 그래프 전체가 따라 움직이고, 노드를 끌면 그 노드만 옮겨진다. 확대는 캔버스(그림을 그리는 화면 영역)의 오른쪽 아래에 있는 +, − 버튼으로 한다.

처음에는 확대하는 방법으로, 모바일에서는 두 손가락을 오므렸다 펴고 PC에서는 Ctrl을 누른 채 휠을 굴리는 방식만 두었다. 그런데 이런 방식은 아는 사람만 사용하게 된다. 그래서 보자마자 누를 수 있는 버튼을 추가했다. 모바일에서도 똑같이 버튼만 누르면 되기 때문에, 손가락 동작을 몰라도 그래프를 확대할 수 있다.

## 미리보기가 못 보여준 흔들림

그런데 여기서 한 번 더 문제를 겪었다. 새로 만든 그래프가 내 미리보기(고친 것을 바로 실행해 보는 화면)에서는 멀쩡했는데, 막상 배포하고 나니 그래프가 심하게 흔들렸다.

원인은 노드들을 화면에 맞추는 계산에 있었다. 이 계산을 **매 프레임(화면을 다시 그리는 매 순간)** 실행하고 있었던 것이다. 노드들은 아직 자리를 잡느라 계속 움직이는데, 그때마다 화면도 함께 확대되고 이동했다. 그렇게 되면 노드와 화면이 서로를 따라다니게 되고, 결국 그래프 전체가 출렁이게 된다. 그래서 매 프레임 실행하던 계산을 지우고, 노드들이 모두 멈추었을 때 한 번만 화면에 맞추도록 고쳤다.

```ts src/pages/graph.astro
const loop = () => {
  tick();        // 점들을 한 칸씩 움직이고
  fitToBbox(); // [!code --]
  draw();        // 화면에 그린다
  // 점들이 다 멈췄을 때(정착), 딱 한 번만 맞춘다
  if (pendingFit) { // [!code ++]
    fitToBbox(); // [!code ++]
    pendingFit = false; // [!code ++]
  } // [!code ++]
};
```

노드들이 움직이는 동안에는 처음 잡아 둔 화면을 그대로 사용한다. 이때 노드는 정해진 상자 안에서만 움직이도록 제한해 두었기 때문에, 화면 밖으로 나갈 일이 없다. 흔들림은 이렇게 해결했다.

> 더 뼈아픈 건, 이 버그를 미리보기로는 끝내 못 봤다는 점이다.

코드상으로 보면, 미리보기는 그래프처럼 움직이는 화면에서 그 움직임을 거의 실행하지 않는다. 그래서 멈춘 화면만 보고 괜찮다고 생각하며 넘어간 것이다. <u>움직여 보아야 드러나는 버그는 도구가 아니라 코드로 따져야 잡힌다</u>는 것을 다시 배우게 되었다.

## 검색 버튼이 위로 튀던 이유

비슷한 종류의 조용한 버그(눈에 잘 띄지 않는 버그)가 검색 화면에도 있었다. '결과 더 보기'를 처음 누르면 화면이 갑자기 맨 위로 올라가 버렸다.

원인은 포커스(화면이 지금 주목하고 있는 자리)였다. 마지막 글까지 모두 불러오면 '결과 더 보기' 버튼은 사라진다. 그런데 버튼이 사라지는 순간, 그 버튼에 있던 포커스가 갈 곳을 잃고 문서의 맨 위로 올라간다. 그렇게 되면 브라우저는 포커스가 옮겨 간 자리로 화면까지 올려 버린다. 그래서 버튼이 사라지기 전에, **포커스를 방금 불러온 결과로 미리 옮겨** 두기로 했다. 이때 함께 넘기는 preventScroll은 포커스는 옮기되 화면은 움직이지 말라는 뜻이다.

```ts src/pages/search.astro
if (done) {
  // 버튼이 사라지기 전에, 포커스를 방금 뜬 결과로 옮긴다
  firstNew.querySelector('.sr-title')?.focus({ preventScroll: true }); // [!code ++]
  moreBtn.hidden = true;
}
```

이제는 '결과 더 보기'를 눌러도 화면이 보던 자리에 그대로 머문다.

## 남은 것

이번에는 새 기능을 만들기보다, 그래프는 손에 더 익도록 하고 검색은 화면이 덜 튀도록 다듬었다.

배운 것은 따로 있다. 보기에는 멀쩡한데 움직여 보면 무너지는 종류의 버그는, 화면을 한 번 보고 넘어가서는 절대 잡히지 않는다. 움직이는 화면일수록 더 의심하면서 보아야 할 것 같다. <span class="tossface">🌱</span>
