이번 회차는 모바일에서부터 시작됐다. 출근길에서 내 블로그를 들여다보다가, 작동은 하는데 어딘가 손 가는 부분들이 하나둘 눈에 들어왔다. [[polish-round-10|지난 글]]에서 글 속에 있는 블록들을 손 보았다면, 이번엔 글과 글 *사이*, 그리고 그 겉의 화면들이었다.

## 그래프가 너무 단조로웠다

[그래프](/graph/) 화면은 글을 점으로, 글 사이 연결을 선으로 그린다. 그런데 점이 전부 같은 파란색이었다. 어느 게 오래된 글이고 어느 게 최근 글인지, 나중에 시리즈가 계속 쌓이게 된다면 점만 봐선 알 수 없었다. 글이 15편까지 쌓이고 보니 그 단조로움이 더 도드라졌다.

그래서 점에 **시간의 농도**를 주기로 했다. 가장 오래된 글은 옅게, 최근 글로 올수록 진하게 칠하기로 했다. 색조는 그대로 두고 진하기만 바꾼다.

```ts src/pages/graph.astro
// 발행된 순서(0=가장 옛, 1=최신)를 색 농도로. Base가 0.5라 옛 글도 너무 옅진 않다
const t = 0.5 + 0.5 * age; // [!code highlight]
return `rgb(${lerp(sr, ar, t)}, ${lerp(sg, ag, t)}, ${lerp(sb, ab, t)})`;
```

이 함수는 글의 발행 시기를 받아, surface(배경) 색과 accent(강조) 색 사이 어디쯤의 색을 돌려준다. 나이가 0(**오래된 글**)이면 배경 쪽으로 절반 희석돼 옅어지고, 1이면(**최근에 올린 글**) 온전한 강조색이 된다. `0.5`라는 Baseline을 둔 건, 가장 오래된 글도 너무 옅어지면 빈 원으로 그린 태그 점과 헷갈리기 때문이다.

라이트 모드에선 옛 글이 흰 배경으로 희석돼 *연한* 파랑이 되고, 다크 모드에선 어두운 배경으로 희석돼 *흐릿한* 파랑이 된다. 두 모드 모두 "옛 글은 가라앉고, 새 글이 또렷하다"는 같은 결을 가진다. **시리즈별로 색을 나누는 건 시리즈가 더 늘면 그때 볼 생각**이다.

## 접었더니 한 번 튕기는 문제 발견

글 아래 '이 글의 만듦새' 패널은 누르면 펼쳐지고 다시 누르면 접힌다. 그런데 접히는 *순간*, 제 높이보다 살짝 더 줄었다가 **도로 튀어 오르는 게** 보였다. 눈에 확 띄진 않아도, 한 번 보이면 계속 거슬리는 부류였다.

원인은 접히는 높이를 잘못 잰 데 있었다. 접는 애니메이션이 노릴 높이를 `summary`(접었을 때 남는 제목 줄)의 높이로만 잡았는데, 정작 이 패널은 테두리 안쪽에 여백(**padding**)을 두르고 있었다. 그 여백만큼 덜 계산해서, 실제 닫힘 높이보다 더 줄였다가 마지막에 도로 채워 넣은 것이다.

```ts src/scripts/smooth-details.ts
// 닫힘 목표 = summary 높이 + 패널 자신의 세로 여백·테두리
const cs = getComputedStyle(d);
const extra = padTop + padBottom + borderTop + borderBottom;   // [!code ++]
run(summary.offsetHeight, () => { d.open = false; });          // [!code --]
run(summary.offsetHeight + extra, () => { d.open = false; });  // [!code ++]
```

`offsetHeight`는 제목 줄 *자신의* 여백은 이미 품고 있어서, **패널 바깥 테두리가 두른 여백만 더해 주면** 닫힘 높이가 정확히 맞는다. 빨간 줄이 옛 계산 산식이고, 초록 줄이 여백을 더한 계산이다. 이러니 접힐 때 더 줄어드는 일 없이, 한 번에 제자리로 돌아간다.

## 연결된 글이 들어온 순서대로였다

글 아래 '연결된 글' 목록은 그동안 연결을 적어 둔 순서대로 떴다. 그러다 보니 *확장*처럼 글의 핵심을 잇는 연결과, *관련*처럼 곁들이로 둔 연결이 뒤섞였다. 게다가 목록은 처음 3개만 보이고 나머지는 접어 두는데, 그 3개가 중요도와 무관하게 뽑혔다.

그래서 **타입 우선순위로 줄을 세웠다.** 확장, 뒷받침, 구체화 같은 **직접적인 연결을 위로**, 관련이나 언급은 아래로 두게 되었다. 같은 타입끼리는 최신 글을 먼저 둔다.

```ts src/utils/graph.ts
const typeOrder = [...Object.keys(EDGE_TYPES), 'mentions'];
return list.sort(
  (a, b) => rank(a.type) - rank(b.type) || ageOf.get(b.slug) - ageOf.get(a.slug), // [!code highlight]
);
```

강조한 줄이 전부다. 타입 순위로 먼저 비교하고, 순위가 같으면(`||`) 최신순으로 비교해 최근 글을 위로 올린다. 마침 타입 순서는 연결 타입을 정의해 둔 곳의 순서를 그대로 따르니, 새 타입을 더해도 정렬이 알아서 따라온다. 이제 처음 보이는 3개가 그 글과 가장 단단히 묶인 연결들이다.

## 펼치면 잠깐 버벅였다

홈에서 시리즈 폴더를 펴면 그 안의 카드들이 펼쳐진다. 커버 없는 글은 본문 첫 다이어그램을 작은 썸네일로 얹는데, 폴더를 펴는 *그 순간* 다이어그램 그리기가 한꺼번에 몰려 펼침이 살짝 끊겼다.

펼침은 0.28초짜리 부드러운 애니메이션이다. 그런데 그 짧은 순간에 다이어그램 도구(mermaid)를 불러오고 여러 장을 그리느라, 화면을 움직이는 일과 그림을 그리는 일이 같은 일손을 두고 다툰 것이다. 그래서 그림 그리기를 **한가해질 때로 미뤘다.**

```ts src/components/SeriesFolder.astro
// 펼침 애니메이션이 먼저 끝나게, 다이어그램 렌더는 한가할 때(idle)로 미룬다
deferIdle(() => renderMermaidDiagrams([el])); // [!code highlight]
```

`deferIdle`은 `requestIdleCallback`(브라우저가 다른 급한 일이 없을 때 **잠깐 짬을 내 실행**해 주는 함수)으로 그리기를 미룬다. 펼침이 먼저 매끄럽게 끝나고, 그림은 곧이어 채워진다.

대신 채워지기 전 빈 칸이 허전해서, 그 자리에 **스켈레톤**(내용이 오기 전 잔잔히 반짝이는 자리표시) **UI**를 깔았다.

```css src/components/SeriesFolder.astro
/* 다이어그램이 그려지기 전(:empty)에만 반짝이는 자리표시 */
.s-thumb .mermaid-diagram:empty {
  background: linear-gradient(90deg, var(--border), var(--surface), var(--border));
  animation: s-thumb-shimmer 1.2s linear infinite; /* [!code highlight] */
}
```

자바스크립트를 한 줄도 안 보태고 끝난 게 마음에 든다. `:empty`는 "안이 빈 요소"만 고르는 선택자라, 다이어그램이 그려져 안이 채워지는 순간 이 규칙은 저절로 풀린다. 빈 동안엔 반짝이고, 그려지면 다이어그램으로 갈아 끼워진다.

## 추가로 다듬은 것들

- **글 보러 가기.** 발행을 누르면 뜨던 '글 보러 가기' 링크가, 모바일에선 상태 문구 아래로 어정쩡하게 떨어져 있었다. 좁은 화면에선 상태 줄을 한 칸으로 펴고 발행 버튼을 그 아래 큼직하게 내렸다. 링크도 그냥 글자가 아니라 누를 곳처럼 보이게 손봤다.

- **너무 붙어 있던 화살표.** 그래프의 '연결 타입 안내'와 글쓰기 화면의 '어떤 타입을 골라야 할까요'에서, 펼침 화살표가 글자에 바짝 붙어 있었다. 반 칸쯤 띄웠다. 작은 것도 작은 채로 고쳐 둔다.

- **코드 블록에 파일명.** 지난 글들의 코드 블록 중엔 **어느 파일에서 가져온 코드인지 안 적힌 게 많았다.** 출처가 분명한 것들만 골라 파일명을 채웠다. 그러다 사소한 걱정이 하나 있었는데, 파일 경로에 든 대괄호(`[slug].astro` 같은)가 글쓰기 화면을 거치며 깨지지 않을까였다. 직접 넣었다 빼 보니 멀쩡해서 다행이었다. 본문 속 대괄호와 달리, 코드 블록의 파일명은 안전한 곳이었다.

## 요약

이번에 고친 것들은 그래프에 시간이 보이게 하고, 접힘이 튀지 않고, 연결이 중요한 순서로 놓이고, 펼침이 매끄러워지게끔 하는 것이었다. 휴대폰을 들고 유심히 둘러본 게 이번엔 꽤 쓸모가 있었던 것 같다. 확실히 **내 블로그라는 애정**이 들어가서 그런지 자잘한 부분들이 계속 보이는 것 같다. 다음엔 또 어느 부분이 눈에 띌지 궁금하다. <span class="tossface">😎</span>
